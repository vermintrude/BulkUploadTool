WHAT THE REPORT MEANS
A release is confirmed only when both the description-update branch and
New Release tag-add branch have reporting markers for the SAME scheduled time.
A partial marker is shown as incomplete evidence, not a Crosslist-ready item.
Query snapshots include zero-match nights. Matching expected/recorded product
counts provides evidence of completed actions for that query, not access to
Shopify's native execution logs or a guarantee of every possible side effect.
Missing marker is unknown, not failed. Saved snapshot date is visible; failed
refreshes retain stale history and explicitly report the read failure.
The original nightly queries are limited to100 products; a full100 is flagged.

RETENTION / CHECKLIST
Shopify keeps the latest stage marker per product and latest query marker per
workflow. They remain while your PC is off. Local Admin accumulates confirmed
product+release-time events and observed query snapshots. It cannot reconstruct
unobserved overwritten events, deleted products or pre-recording history. It is
not a full hosted event archive. Titles/SKUs/links reflect current product data.
The first variant SKU is shown; additional variants are flagged for review.
Done status is local, reversible and survives repeat reads/reloads. Mark done
only after you have handled the product in Crosslist. It never publishes.
New localStorage key: comicrox_shopify_actions_v1. Old keys untouched.
Download a private checklist backup periodically and before changing browsers.
Restore replaces only this report's local history/checklist with confirmation.
