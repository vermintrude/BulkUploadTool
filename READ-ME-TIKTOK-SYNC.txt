STEP1 — SOURCES
Download a FRESH full Shopify CSV. Download TikTok All information XLSX files for Live, Failed/Needs attention, Deactivated and Draft. Label each upload using the source-status selector; the exported status cell can incorrectly say Live for Failed listings. ZIPs containing multiple XLSX files are supported. Include stock quantities. Check each complete/empty confirmation only after exporting all products for that status or verifying the status is empty. Sources are kept in browser memory, not saved externally. No cloud upload.

STEP2 — PACKING
Enter actual packed weight in grams and dimensions in cm. Default SINGLE145g33x21x0.5cm comes from owner's confirmation; it is not measured by the app. Graded/bundle defaults blank; enter measured profile or per-item values. Copies in stock do not determine parcel thickness. Preorder-tagged products, missing images, unsupported category and multiple variants are held. Decimal0.5cm is retained; if TikTok rejects it, check the actual parcel/accepted field units before rounding. An optional NEW TikTok create template can replace bundled prior working template; Bulk edit templates rejected. Bundled template contains no owner's product rows.

STEP3 — MATCHING / CHECKLISTS
Shopify master eligibility requires active+published+positive stock. Entire Shopify catalogue is used to distinguish archived/unpublished/out-of-stock from absent. Exact normalized title match or an explicitly confirmed stored TikTokID-to-Shopifyvariant link counts as same product. Unique SKU and title narrow multi-variant cases; SKU alone never proves identity. Reused codes, changed titles, approximate candidates and unmatched TikTok rows require manual review. In Check identity manually, select a candidate and Confirm same product only after checking issue, edition, grade and variant. No confident master match is not automatic proof of a sale; it stays in review. Confirm packing/availability via held-row controls only if accurate.

On screen: Ready additions; Remove/zero-stock recommendations with TikTok IDs and source status; Check identity; Held products; Existing stock/price differences. CSV/XLSX review downloads come from the LOCAL APP, not chat. They are not import files. Change/deactivate listings manually; never delete the whole catalogue to use additions.

STEP4 — CREATE
Confirm all four status coverages and packing, then download additions XLSX. It preserves create-template headers/support sheets and removes all prior product rows. Positive price/stock, public image URLs and confirmed numeric parcels required. Unique internal TikTok SKUs created where Shopify SKUs blank/reused/collide; mappings persist without changing Shopify SKUs. Review workbook includes stored mappings after generation. Use TikTok Bulk actions → Upload in bulk (NOT Bulk edit → Upload). Check actual TikTok validation before publishing. Source snapshots become stale after subsequent sales; rerun on fresh exports.

STEP5 — OUTCOME / SAFE RETRIES
Generation saves a run with its actual workbook and marks rows pending BEFORE download. Those rows cannot be regenerated while pending/successful. Download the SAME saved file from run history after a failed download or browser reload; this only retries delivery, not upload. Never upload the same file twice after rows succeeded. Record successful seller SKUs explicitly. Only release failed/not-uploaded SKUs after checking TikTok; confirmed-success rows cannot be released. Then compare again to produce only eligible retry rows. This tool cannot automatically discover TikTok upload outcomes. Download backup before moving browsers; browser storage failures block generation rather than losing the run record. If browser storage fills, preserve backup before making any clearing decision.
